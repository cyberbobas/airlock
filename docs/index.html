Airlock — a runtime firewall for AI coding agents

Gate every tool call, MCP call and skill your agent runs against a least-privilege policy. Static scanners check a skill once, before install. Airlock sits in the call path and decides this call, right now — where a skill that reads clean and behaves badly actually gets stopped.

pipx install airlock-agent      # or: brew install airlock (soon)
airlock init                    # wire the hook, wrap your MCP servers
airlock doctor                  # confirm what is actually enforcing

What it does

Gates the call, not the prose

A poisoned skill can say anything. Airlock refuses the call by what it touches — a secret path, a known collector, download-and-execute.

Every agent's MCP

One stdio proxy gates Claude Code, Cursor, Windsurf, Cline, Continue and Claude Desktop the same way. init finds them all.

Tamper-evident audit

Every decision lands in a hash-chained, optionally signed log. airlock verify proves nothing was rewritten.

Writes its own policy

Run a week in observe, then airlock policy propose hands you the least-privilege rules that cover what your agents actually did.

Onboard in three commands

airlock profile yolo            # week one: learn, block nothing
airlock policy propose --apply  # turn the week into least-privilege grants
airlock profile default         # now guard

Watch it work live with airlock monitor, and scan skills before they merge with the Airlock GitHub Action.

Honest about its limits

Airlock does not stop prompt injection — nothing does; it gates the action the injection asks for. Egress is argument-level. An agent with a shell can start a server outside the proxy. These boundaries are documented, not hidden.
